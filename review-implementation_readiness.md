- **Major — `workbook.js`, lesson 4-6 input and scoring.** The design requires equation pairs, a shared product, units, and a model or drawing, but does not specify which parts learners enter, how they enter units, or whether the model is assessed. The new typed-box type accepts only integers. Define the fields and expected answers for each of the three 4-6 prompt kinds, and state how the model or drawing participates in submission and scoring.

- **Major — `workbook.js`, primary and twin generation.** The design requires selecting from finite pools but does not define the selection algorithm or how it guarantees that every reserved primary can still receive a distinct twin. A pool large enough in aggregate can still produce a dead end after primary selection. Specify reservation or allocation rules that guarantee a twin for each primary before the session starts, and define the visible failure behavior if allocation fails.

- **Major — `workbook.js`, multi-typed-box data and feedback.** The design names token properties and integration functions but leaves the problem schema and answer mapping unspecified. In particular, it does not define how literal tokens, keyed blanks, field state, and completed-equation feedback relate to one another. Define the problem and token shapes, collected-answer shape, and rendering/checking contract so repeated values and independently entered blanks are handled consistently.

- **Major — `workbook.js`, 5-1 review and array model.** The review requires a worked equation and truthful visual, but the design does not specify the example operands, split, or the visual representation to render. It also leaves the split-array boundary and its accessible description undefined. Specify the review example and the model’s visual and spoken representation so the equations, split, and feedback can be implemented consistently.

- **Major — Execution plan and checkpoints.** The design lists affected files and acceptance checks but does not partition implementation into incremental phases with stable, testable checkpoints, as required by the implementation-readiness standard. Specify the order of changes and the verification that establishes each checkpoint.
